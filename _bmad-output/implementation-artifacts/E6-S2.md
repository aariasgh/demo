## 📖 Historia de Usuario

**Como** usuario del CRM (ejecutivo, manager, stakeholder)  
**Quiero** ver estados visuales claros cuando el sistema está cargando, procesando o mostrando errores  
**Para que** entienda qué está pasando, no piense que la app se congó, y pueda recuperarme de errores fácilmente  

### Problema que Resuelve

- **Blank screen syndrome:** Datos tardados en cargar → usuario piensa app está roto
- **No feedback on submit:** Presiono "Crear Lead" → ¿se envió? ¿qué pasó?
- **Silent failures:** API error → nada pasa → usuario no sabe que falló
- **Empty confusion:** 0 leads → pantalla blanca → ¿hay bug? ¿cargó?
- **No recovery path:** Error ocurre → no hay botón "reintentar"

### Valor de Negocio

- **Confianza:** El app se siente responsivo y profesional
- **UX pulida:** Loading/error states = percepción de calidad
- **Accesibilidad:** `@media (prefers-reduced-motion)` cumple WCAG AA
- **Retención:** Users no abandonan por percepción de congelamiento

### **Responsive Breakpoints (De E6-S1)**

```
- sm: 640px (mobile large)
- md: 768px (tablet)
- lg: 1024px (desktop small)
- xl: 1280px (desktop large)
```

### **Color System (Established)**

```
Primary (info):     #3B82F6 (blue)
Success:            #10B981 (green)  →  Light: #D1FAE5, Dark: #065F46
Error:              #DC2626 (red)    →  Light: #FEE2E2, Dark: #7F1D1D
Warning:            #F59E0B (amber)  →  Light: #FEF3C7, Dark: #78350F
```

### **Timing Standards (Established)**

```
Fast:    150ms (form validation feedback)
Normal:  200ms (modal fade, card transitions)
Slow:    300ms (page transitions)
Easing:  ease-in-out (default), ease-out (exit animations)
```

### **Performance Guardrails**

- ✅ CSS animations only (no JS animations for performance)
- ✅ Use GPU acceleration: `transform` and `opacity` ONLY
- ✅ Avoid layout properties: NO `width`, `height`, `margin` changes in animations
- ✅ `will-change: transform` for expensive animations
- ✅ 60fps requirement: use DevTools performance profiler

```tsx

```

**For E6-S2:** Use this as standard for all state changes (loading → data, visible → hidden, etc.)

### **Code Conventions Established**

- `className` destructure at component top
- `aria-label`, `aria-live` for accessibility
- Touch targets ≥ 44px minimum (maintained in buttons)
- Tailwind utilities only (no inline styles)
- Component composition over complex JSX

### **Testing Approach Used**

E6-S1 tests covered:
- Breakpoint-specific rendering
- Touch target sizes
- Typography scaling

**For E6-S2:** Add tests for:
- Loading state visibility
- Error state with retry
- Empty state rendering
- Toast notification lifecycle
- Animation durations (use `jest.useFakeTimers()`)

### **Common Mistakes to Avoid**

❌ **DON'T:** Use `display: none/block` for loading states (causes layout thrashing)  
✅ **DO:** Use `opacity` and `transform` only (GPU-accelerated)

❌ **DON'T:** Forget `aria-live="polite"` on toast notifications  
✅ **DO:** Add `role="status"` to all dynamic content

❌ **DON'T:** Leave animations in production without `@media (prefers-reduced-motion)` support  
✅ **DO:** Reduce durations to 50ms for users with vestibular disorders

## 🎨 Animation Specifications

### **Timing Matrix**

| Component | Action | Duration | Easing | GPU? |
|-----------|--------|----------|--------|------|
| Spinner | Rotation | 1s infinite | linear | ✓ transform: rotate |
| Modal | Fade-in | 200ms | ease-in-out | ✓ opacity |
| Modal | Fade-out | 200ms | ease-in-out | ✓ opacity |
| Toast | Slide-in | 200ms | ease-out | ✓ transform: translateY |
| Card | Hover | 200ms | ease-in-out | ✓ transform: scale, box-shadow |
| Skeleton | Pulse | 1.5s infinite | ease-in-out | ✓ opacity |
| Button | Loading (icon spin) | 1s infinite | linear | ✓ transform: rotate |

### **CSS Implementation**

```css
/* Tailwind utilities for standard timing */
.transition-all { transition: all 200ms ease-in-out; }
.duration-200 { animation-duration: 200ms; }
.ease-in-out { animation-timing-function: ease-in-out; }

/* Custom animations (add to tailwind.config.js) */
@keyframes spin-custom {
  from { transform: rotate(0deg); }
  to { transform: rotate(360deg); }
}

@keyframes pulse-custom {
  0%, 100% { opacity: 0.3; }
  50% { opacity: 0.6; }
}

@keyframes slide-in-bottom {
  from {
    transform: translateY(100%);
    opacity: 0;
  }
  to {
    transform: translateY(0);
    opacity: 1;
  }
}

/* Accessibility: respect prefers-reduced-motion */
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 50ms !important;
    transition-duration: 50ms !important;
  }
}
```
