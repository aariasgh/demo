## 🏗️ ARCHITECTURE COMPLIANCE

### Stack Técnico Obligatorio (Per Winston — Architect)

Este story DEBE cumplir estas decisiones arquitectónicas (NO NEGOCIABLES):

| Component | Technology | Version | Rationale | Risk |
|-----------|-----------|---------|-----------|------|
| **Framework** | React | 18.2+ | Modern hooks, suspense ready, largest community | ZERO — used by 40% of web |
| **Language** | TypeScript | 5.0+ | Type safety, better DX, fewer bugs at runtime | ZERO — we use strict mode |
| **Build Tool** | Vite | 4.3+ | Fast dev server, optimized builds, <2MB possible | MEDIUM (new) but battle-tested |
| **State Mgmt** | Zustand | 4.4+ | Lightweight (~2KB), TypeScript first, simple API | LOW — proven in production |
| **HTTP + Caching** | TanStack Query | 5.0+ | Auto dedup, stale-while-revalidate, auto refetch | LOW — industry standard |
| **Drag & Drop** | react-beautiful-dnd | 13.1+ | Kanban-standard, accessible, smooth animations | MEDIUM (not maintained but stable) |
| **CSS Framework** | Tailwind CSS | 3.3+ | Utility-first, small bundles with purging, responsive | LOW — established standard |
| **HTTP Client** | axios | 1.4+ | Interceptors for retry, timeout, error handling | ZERO — battle-tested |
| **Linting** | ESLint + Prettier | latest | Format consistency, catch errors early | ZERO |
| **Container** | Docker | 20.10+ | Multi-stage build, <200MB image | ZERO |

### Decisiones Arquitectónicas Críticas Que Afectan a E1-S3

**Decision #1: Vite (NO Webpack o Create React App)**
- ✅ ES modules nativo (200x más rápido que webpack)
- ✅ HMR (hot module replacement) instantáneo
- ✅ Build optimizado por defecto
- ❌ Algunos polyfills viejos no funcionan (pero no los necesitamos)
- **Implication:** React Router debe estar en 6.4+ compatible con Vite

**Decision #2: Zustand (NO Redux)**
- ✅ Descentralizado: cada store en su archivo
- ✅ TypeScript first: inferencia automática
- ✅ Lightweight: ~2KB minified
- ❌ Menos middleware que Redux (pero no lo necesitamos)
- **Implication:** No hay combineReducers, cada store es independiente

**Decision #3: TanStack Query (NO manual fetch)**
- ✅ Dedup automático: 5 requests iguales = 1 fetch
- ✅ Stale-while-revalidate: muestra cache viejo mientras refetch
- ✅ Retry automático con backoff exponencial
- ❌ Curva de aprendizaje: queryKey patterns son importantes
- **Implication:** queryKey DEBE ser un array, nunca un string

**Decision #4: Tailwind + CSS Modules (NO Styled Components)**
- ✅ Tailwind: small bundle (~20KB), purging automático
- ✅ CSS Modules: scoped styles, no conflicts
- ❌ Aprendizaje inicial de utilidades Tailwind
- **Implication:** No global styles, todo es modular

**Decision #5: Docker Multi-stage (node:18-alpine + nginx:alpine)**
- ✅ Stage 1: Build con node (instala deps, compila TS, bundle)
- ✅ Stage 2: Runtime con nginx (solo output estático)
- ✅ Final image: <200MB (sin node en prod)
- ❌ Debugging en producción es más difícil
- **Implication:** Local dev usa Vite dev server, prod usa nginx

### Critical "Don't Do This" List

Based on common LLM mistakes:

❌ **DON'T:** Use `useEffect` for data fetching  
✅ **DO:** Use TanStack Query's `useQuery`  
Why: Query handles refetch, caching, stale-while-revalidate automatically

❌ **DON'T:** Store API data in Zustand store  
✅ **DO:** Let TanStack Query manage cache, use Zustand only for UI state  
Why: Double source of truth = bugs, Query already handles server state

❌ **DON'T:** Use `any` type in TypeScript  
✅ **DO:** Use strict types, `unknown` if needed  
Why: Defeats entire purpose of TypeScript

❌ **DON'T:** Import from Zustand store in Zustand store (circular)  
✅ **DO:** Keep stores independent, compose in components  
Why: Zustand intentionally avoids Redux's complexity

❌ **DON'T:** Use CSS-in-JS for styling  
✅ **DO:** Use Tailwind + CSS Modules  
Why: Performance + consistency + bundle size

❌ **DON'T:** Hardcode API URLs in components  
✅ **DO:** Use .env.local + import.meta.env.VITE_*  
Why: Environment-agnostic code

❌ **DON'T:** Leave console.logs in production code  
✅ **DO:** Use // debug comments if necessary  
Why: ESLint catches this, smaller bundle

#### `src/services/api.ts`

```typescript
import axios from 'axios';

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8000';

const client = axios.create({
  baseURL: `${API_BASE_URL}/api`,
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json',
  },
});

// Retry interceptor with exponential backoff
client.interceptors.response.use(
  (response) => response,
  async (error) => {
    const config = error.config;
    if (!config || !error.response || error.response.status < 500) {
      return Promise.reject(error);
    }

    config.__retryCount = config.__retryCount || 0;
    if (config.__retryCount >= 3) {
      return Promise.reject(error);
    }

    config.__retryCount += 1;
    const delay = Math.pow(2, config.__retryCount) * 100;
    await new Promise((resolve) => setTimeout(resolve, delay));

    return client(config);
  }
);

export default client;
```

```typescript
import { create } from 'zustand';
import { Lead, LeadUpdate } from '../types';

interface LeadsState {
  leads: Lead[];
  selectedLeadId: number | null;

  setLeads: (leads: Lead[]) => void;
  addLead: (lead: Lead) => void;
  updateLead: (id: number, partial: Partial<Lead>) => void;
  deleteLead: (id: number) => void;
  selectLead: (id: number | null) => void;
}

export const useLeadsStore = create<LeadsState>((set) => ({
  leads: [],
  selectedLeadId: null,

  setLeads: (leads) => set({ leads }),
  addLead: (lead) => set((state) => ({ leads: [...state.leads, lead] })),
  updateLead: (id, partial) =>
    set((state) => ({
      leads: state.leads.map((l) => (l.id === id ? { ...l, ...partial } : l)),
    })),
  deleteLead: (id) =>
    set((state) => ({
      leads: state.leads.filter((l) => l.id !== id),
    })),
  selectLead: (id) => set({ selectedLeadId: id }),
}));
```

```typescript
import { useQuery } from '@tanstack/react-query';
import { Lead } from '../types';
import client from '../services/api';

export const useLeads = () => {
  return useQuery({
    queryKey: ['leads'],
    queryFn: async () => {
      const response = await client.get<{ leads: Lead[] }>('/leads');
      return response.data.leads;
    },
    staleTime: 1000 * 60 * 5, // 5 min
  });
};

export const useSearchLeads = (q: string) => {
  return useQuery({
    queryKey: ['leads', 'search', q],
    queryFn: async () => {
      if (q.length < 2) return [];
      const response = await client.get<{ results: Lead[] }>('/leads/search', {
        params: { q },
      });
      return response.data.results;
    },
    enabled: q.length >= 2,
  });
};

export const useLeadTimeline = (leadId: number) => {
  return useQuery({
    queryKey: ['leads', leadId, 'timeline'],
    queryFn: async () => {
      const response = await client.get(`/leads/${leadId}/timeline`);
      return response.data.events;
    },
  });
```

#### `src/hooks/useLeadMutations.ts`

```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { Lead, LeadCreate, LeadUpdate } from '../types';
import client from '../services/api';
import { useUIStore } from '../store/uiStore';

export const useCreateLead = () => {
  const queryClient = useQueryClient();
  const showToast = useUIStore((state) => state.showToast);

  return useMutation({
    mutationFn: async (lead: LeadCreate) => {
      const response = await client.post<{ lead: Lead }>('/leads', lead);
      return response.data.lead;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['leads'] });
      showToast('Lead creado exitosamente', 'success');
    },
    onError: () => {
      showToast('Error al crear lead', 'error');
    },
  });
};

export const useUpdateLead = () => {
  const queryClient = useQueryClient();
  const showToast = useUIStore((state) => state.showToast);

  return useMutation({
    mutationFn: async ({ id, data }: { id: number; data: Partial<Lead> }) => {
      const response = await client.patch<{ lead: Lead }>(`/leads/${id}`, data);
      return response.data.lead;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['leads'] });
      showToast('Lead actualizado', 'success');
    },
    onError: () => {
      showToast('Error al actualizar lead', 'error');
    },
  });
};

export const useDeleteLead = () => {
  const queryClient = useQueryClient();
  const showToast = useUIStore((state) => state.showToast);

  return useMutation({
    mutationFn: async (id: number) => {
      await client.delete(`/leads/${id}`);
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['leads'] });
      showToast('Lead eliminado', 'success');
    },
    onError: () => {
      showToast('Error al eliminar lead', 'error');
    },
  });
};

export const useValidateEmail = () => {

    },
  });
```

## 🎓 DEVELOPER NOTES & GUARDRAILS

### Critical Implementation Patterns

#### Pattern #1: Never Store Server State in Zustand

❌ **WRONG:**
```typescript
// In a component
const createMutate = useMutation(...);
const leadsStore = useLeadsStore();

onSuccess: () => {
  leadsStore.setLeads(newLeads); // WRONG: double source of truth
}
```

✅ **RIGHT:**
```typescript
// TanStack Query handles cache automatically
const createMutate = useMutation({
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ['leads'] }); // Trigger re-fetch
  }
})
```

#### Pattern #2: Query Keys Must Be Arrays

❌ **WRONG:**
```typescript
queryKey: 'leads' // STRING — causes issues with dedup
```

✅ **RIGHT:**
```typescript
queryKey: ['leads'] // ARRAY — automatic dedup
queryKey: ['leads', 'search', q] // Nested arrays for hierarchy
```

#### Pattern #3: Debounce Search Input

❌ **WRONG:**
```typescript
onChange={(e) => setSearchQuery(e.target.value)} // Fires 10+ queries per second
```

✅ **RIGHT:**
```typescript
// In component
const [searchQuery, setSearchQuery] = useState('');
const debouncedQuery = useDebounce(searchQuery, 300); // Wait 300ms after typing stops
const { data } = useSearchLeads(debouncedQuery); // Only query when debounce settles
```

#### Pattern #4: Optimistic Updates

```typescript
// Optimistic update: show change immediately, rollback if error
const updateMutate = useMutation({
  onMutate: async (newData) => {
    // Cancel any outgoing queries
    await queryClient.cancelQueries({ queryKey: ['leads'] });
    
    // Optimistically update cache
    const previousLeads = queryClient.getQueryData(['leads']);
    queryClient.setQueryData(['leads'], (old) =>
      old.map(l => l.id === newData.id ? { ...l, ...newData } : l)
    );
    
    return { previousLeads };
  },
  onError: (err, newData, context) => {
    // Rollback on error
    queryClient.setQueryData(['leads'], context?.previousLeads);
  },
});
```

### Anti-Patterns to Avoid

| Anti-Pattern | Why It's Bad | Fix |
|-------------|-------------|-----|
| `useEffect` for data fetch | No dedup, caching, retry | Use `useQuery` |
| Server state in Zustand | Sync issues, bugs | Use TanStack Query cache |
| `any` type in TS | Defeats type safety | Use `unknown` or proper types |
| Global CSS | Style conflicts | Use CSS Modules + Tailwind |
| Hardcoded API URLs | Not environment-agnostic | Use `.env.local` + `import.meta.env` |
| `console.log` in prod | Pollutes bundle | Use `// debug` comments |
| Props drilling 10 levels deep | Unmaintainable | Use Zustand stores or Context |
| Circular imports | Build errors | Keep stores independent |

### Performance Optimization Techniques

**Technique #1: Lazy Loading Components**
```typescript
const KanbanBoard = lazy(() => import('./components/KanbanBoard'));
const Suspense: <Suspense fallback={<Loading />}><KanbanBoard /></Suspense>;
```

**Technique #2: Memoization**
```typescript
const LeadCard = memo(({ lead, onSelect }) => ...);
// Only re-renders if lead or onSelect changes
```

**Technique #3: Query Staleness**
```typescript
useQuery({
  queryKey: ['leads'],
  queryFn: ...,
  staleTime: 1000 * 60 * 5, // 5 min — don't re-fetch immediately
});
```
