## 🎯 STORY REQUIREMENTS

### User Story Statement

**Como** desarrollador,  
**quiero** ejecutar un único comando `docker-compose up` desde la raíz del proyecto,  
**para que** el stack completo (Frontend + Backend + PostgreSQL) esté listo en 20 segundos sin fricción, permitiendo desarrollo sin problemas de dependencias.

### Business Value

- ✅ Ambiente reproducible: "funciona en mi máquina" → funciona en cualquier máquina
- ✅ Velocidad: desarrollo sin instalar dependencias globales
- ✅ Colaboración: nuevo dev hace `git clone && docker-compose up` y listo
- ✅ DevOps ready: mismo docker-compose.yml sirve de base para staging/producción
- ✅ Debugging: `make logs-backend` acceso inmediato a logs
- ✅ Reset limpio: `make reset` borra todo y reinicia (desarrollo ágil)

## 🎓 ARCHITECTURE PATTERNS

### Pattern: Service Discovery
**How it works:** Frontend at `localhost:3000` calls `http://localhost:8000/api/...` via Vite proxy  
**In Docker:** Frontend container calls `http://backend:8000/api/...` using service name  
**Key:** docker-compose creates internal DNS so containers find each other by service name

### Pattern: Health Checks
**Why:** docker-compose waits for `depends_on` service to be healthy before starting dependent services  
**Benefits:** No "connection refused" errors during startup; guaranteed service is ready

### Pattern: Volume Mounts for Development
**Why:** Code changes immediately visible without rebuild  
**Backend:** `./backend:/app/backend` + uvicorn --reload  
**Frontend:** `./frontend:/app/frontend` + Vite HMR  
**Database:** `postgres_data:/var/lib/postgresql/data` (named volume for persistence)

### Pattern: Environment-Specific Configuration
**How:** `.env` file read by docker-compose; `ENVIRONMENT=development` triggers uvicorn --reload  
**Benefits:** Same Dockerfile works for dev and prod (conditional behavior)
