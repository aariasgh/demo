## 🎯 STORY REQUIREMENTS

### User Story Statement

**Como** ejecutivo de venta,  
**quiero** hacer click en "+ Nuevo Lead" y rellenar un modal intuitivo,  
**para que** crear un lead sea rápido (<30 segundos) sin dejar de ver el pipeline.

### Business Value

- ✅ **Speed:** Crear lead en <30s sin dejar el dashboard
- ✅ **UX Quality:** Validaciones inline, feedback inmediato, no recargas de página
- ✅ **User Confidence:** Visual feedback claro (spinner, error messages, toasts)
- ✅ **Data Integrity:** Validaciones client + server prevent bad data
- ✅ **Accessibility:** Form accessible (labels, ARIA, keyboard navigation)

### Form State Management Pattern (Per Architecture)

```typescript
// Use react-hook-form for local form state
const { register, handleSubmit, watch, formState: { errors, isSubmitting } } = useForm<LeadCreate>({
  resolver: zodResolver(LeadCreateSchema),
  mode: 'onBlur', // Validate on field blur
});

// Use TanStack Query for server mutation
const { mutate: createLead, isPending } = useMutation({
  mutationFn: async (data: LeadCreate) => {
    const response = await fetch('/api/leads', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    });
    if (!response.ok) throw new Error(await response.text());
    return response.json();
  },
  onSuccess: (lead) => {
    uiStore.showToast(`✓ Lead '${lead.name}' creado exitosamente`, 'success');
    uiStore.closeCreateModal();
    // Invalidate queries to refetch leads
    queryClient.invalidateQueries({ queryKey: ['leads'] });
  },
  onError: (error) => {
    uiStore.showToast(`Error: ${error.message}`, 'error');
  },
});

// Use Zustand for UI state
const { isCreateModalOpen, openCreateModal, closeCreateModal, showToast } = useUIStore();
```

## 📋 CRITICAL DEPENDENCIES & GOTCHAS

### ⚠️ Gotcha 1: Email Validation - Backend Endpoint Missing

**Problem:** Spec says "validate email duplicates via `GET /api/leads/validate-email`"  
**Status:** Endpoint does NOT exist in backend yet

**Solution:**
- [ ] For MVP: Skip server-side email duplicate check (only validate format client-side)
- [ ] On form submit, if error 409, tell user "Email already exists"
- [ ] Future work (E2-S4-variant): Add `/api/leads/validate-email` endpoint

**OR:** Implement validation on first field blur (after E3-S1 is done):
```typescript
// After E3-S1 adds GET /api/leads endpoint, we can check:
const existingLeads = await fetch('/api/leads').then(r => r.json());
const isDuplicate = existingLeads.some(l => l.email === formEmail);
```

### ⚠️ Gotcha 2: Query Invalidation Timing

**Problem:** After creating lead, Kanban might not show new lead if query not invalidated

**Solution:**
```typescript
onSuccess: (lead) => {
  // MUST invalidate the leads query to trigger refetch
  queryClient.invalidateQueries({ queryKey: ['leads'] });
  // This ensures E3-S2 (Kanban) sees the new lead immediately
},
```

### ⚠️ Gotcha 3: Form State Cleanup on Close

**Problem:** User fills form, closes modal, opens again → data still there (confusing UX)

**Solution:**
```typescript
onClose: () => {

```

**Problem:** `LeadCreate` might not match exact API schema

**Solution:**
- [ ] Export Zod schema from backend (via API docs)
- [ ] Import same schema in frontend
