### Database Connection Pattern

```python
# app/database/core.py
# Pattern from Winston's architecture

from sqlalchemy.ext.asyncio import (
    create_async_engine,
    AsyncSession,
    async_sessionmaker,
)

# Engine with async+asyncpg
engine = create_async_engine(
    f"postgresql+asyncpg://{DB_USER}:{DB_PASSWORD}@{DB_HOST}:{DB_PORT}/{DB_NAME}",
    echo=False,  # Set to True only in dev if debugging
    pool_size=5,        # Min connections
    max_overflow=20,    # Max overflow beyond pool_size
    pool_pre_ping=True, # Verify connection health before using
)

# Session factory
async_session_maker = async_sessionmaker(
    engine,
    class_=AsyncSession,
    expire_on_commit=False,  # Don't expire objects after commit (we handle manually)
)

async def get_db():
    """Dependency for FastAPI: provides async session"""
    async with async_session_maker() as session:
        try:
            yield session
        finally:
            await session.close()
```

**Why This Pattern:**
- `pool_pre_ping=True`: Prevents "lost connection" errors
- `async_sessionmaker`: Proper async context management
- Dependency injection: FastAPI can inject session into routes
- `expire_on_commit=False`: Better control over object lifecycle

### Health Check Endpoint Pattern

```python
# app/routers/health.py

from fastapi import APIRouter
from datetime import datetime

router = APIRouter(prefix="/api", tags=["health"])

@router.get("/health", tags=["health"])
async def health_check():
    """
    Health check endpoint. Returns 200 if backend is running.
    
    Used by Docker healthcheck directive and monitoring.
    """
    return {
        "status": "ok",
        "timestamp": datetime.utcnow().isoformat() + "Z",
    }
```

**Why This Endpoint:**
- Docker healthcheck depends on 200 response
- Monitoring tools ping this for uptime
- Super fast — no DB query required
- Tells you backend is alive (not that DB is alive — that's separate concern)

## 🔧 TECHNICAL REQUIREMENTS

### FastAPI Initialization

**app/main.py** must:

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from app.routers import health

app = FastAPI(
    title="Mini CRM API",
    description="Backend para Mini CRM de Seguimiento de Clientes",
    version="0.1.0",
)

# CORS: Allow frontend at localhost:3000
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],  # Frontend URL
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# Register routers
app.include_router(health.router)

@app.on_event("startup")
async def startup():
    """Runs when FastAPI starts"""
    # Log startup info
    print("🚀 Backend started")

@app.on_event("shutdown")
async def shutdown():
    """Runs when FastAPI shuts down"""
    # Close DB connections
    print("🛑 Backend stopped")
```

**Why This Structure:**
- CORS allows frontend requests from localhost:3000
- title/description show up in Swagger docs
- startup/shutdown events ensure proper resource management
- Router registration keeps code modular

### Docker Healthcheck

**docker-compose.yml** must include:

```yaml
backend:
  build: ./backend
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8000/api/health"]
    interval: 10s
    timeout: 5s
    retries: 3
    start_period: 30s
```

**Why This Matters:**
- `docker-compose up` won't start dependent services until health check passes
- `start_period: 30s`: Gives backend time to initialize before first check
- If health check fails 3 times → container marked as unhealthy
- Docker Compose respects this for startup ordering

### Volume Mounts for Hot Reload

**docker-compose.yml** must mount source code:

```yaml
backend:
  volumes:
    - ./backend:/app/backend
    - /app/backend/__pycache__  # Exclude pycache
  environment:
    - PYTHONUNBUFFERED=1  # Important: flush logs immediately
```

**Why This Works:**
- `./backend:/app/backend`: Source code changes trigger Uvicorn reload
- `PYTHONUNBUFFERED=1`: Logs appear immediately in `docker-compose logs`
- Without this, every change requires `docker-compose down && up` (slow!)

### Connection Pool Settings

**Key insight from Winston:**

> "Connection pool size 5-20 is right for demo. For production 100+ concurrent users, scale to 100-200."

Your code must use:
```python
pool_size=5,        # Min connections in pool
max_overflow=20,    # Max additional connections beyond pool_size
```

**Production Note:** If you see "QueuePool limit exceeded" errors later, increase these numbers. For this demo, 5+20=25 max connections is plenty for 1-2 concurrent users.
