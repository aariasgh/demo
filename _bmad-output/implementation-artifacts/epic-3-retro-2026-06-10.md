### E3-S3: Drag & Drop - Frontend Kanban Drag-Drop
| Aspecto | Valor |
|--------|-------|
| **Story Points** | 13 |
| **Duración** | 2 horas (faster than 3.5h estimate) |
| **Status** | ✅ Done |
| **Tests** | 7/7 KanbanBoard passing (no pre-existing failures) |
| **Code Review** | 6 security/UX patches identificadas y aplicadas |

**Logros Clave:**
- useKanbanDragDrop custom hook completo
- Optimistic updates (local state → backend sync)
- Error recovery (rollback en caso de fallo)
- Retry logic (3 retries con exponential backoff)
- 5-second network timeout con AbortController
- Todos 12 AC satisfechos

**Code Review Patches (6 security/UX critical):**
- **H1.1 (Security):** Add regex validation para draggable IDs
  - Pattern: `/^lead-(\d+)$/`
  - Previene: NaN errors, ID injection
  
- **H1.3 (Security):** Add status validation en mutation
  - Valida que status es uno de 4 valores válidos
  - Previene: API call con status inválido
  
- **H2.5 (Reliability):** Add network timeout (5000ms)
  - AbortController con timeout
  - Previene: indefinite pending state
  
- **H1.2 (UX):** Error differentiation (4xx vs 5xx vs timeout)
  - 4xx: Client error (bad data)
  - 5xx: Server error (retry)
  - Timeout: Network error (retry)
  - Beneficio: User sabe qué hacer
  
- **AC-7 (UX):** Export isPending flag para prevent concurrent drags
  - isDropDisabled en columns
  - Beneficio: No puede drag mientras sync en progreso
  
- **AC-12 (Accessibility):** Enhanced aria-labels con estado
  - Antes: "Lead: John"
  - Después: "Lead: John Doe de Acme Corp. Estado: Nuevo. Arrastra para cambiar estado."
  - Beneficio: Screen readers narran contexto completo

**Lecciones:**
- Input validation es FUNDAMENTAL (no usar naive parsing)
- Network timeouts protegen UX (no indefinite waits)
- Error messages específicas mejoran UX (saber qué salió mal)
- Concurrency control previene race conditions
- Accessibility text debe ser descriptiva, no genérica

### 🔒 Lección 5: Input Validation es FUNDAMENTAL
**Descubrimiento:** E3-S3 encontró falta de regex validation en draggable ID parsing  
**Evidencia:**
- Patch H1.1: `/^lead-(\d+)$/` regex validation
- Sin ella: "lead-abc" → NaN → crash
- Con ella: "lead-abc" → rejected → error toast

**Análisis:**
- "Trust but verify" no funciona con user input
- Regex + type coercion + boundary checks = layered validation
- Backend debe também validar (defense in depth)

**Aplicación a E4:**
- Spec debe incluir validation rules explícitamente
- "Validate search query" → "Max 100 chars, no special chars except space/dash"
- AC deben incluir invalid input test cases
