### 🎓 Code Patterns Established
1. **Async/Await Pattern:** All database operations are async
   ```python
   async def get_db():
       async with async_session_maker() as session:
           try:
               yield session
           except Exception:
               await session.rollback()
               raise
   ```
   - Apply this pattern in all CRUD endpoints (E2+)

2. **Error Logging Pattern:** Structured logging with logger.info/logger.error
   - Use in migration logs: `logger.info("Migration 0001: Created leads table")`

3. **Configuration Hierarchy:** .env file → Pydantic Settings → runtime
   - Alembic accesses DB via `settings.DATABASE_URL`

### ⚠️ Gotchas to Avoid
1. **Async SQLAlchemy:** NEVER use `engine.begin()` — only async context managers
2. **Default Values:** Don't use `datetime.now()` in default — use `func.now()` from SQLAlchemy
3. **Migrations:** Downgrade must be reversible — don't drop data permanently unless intended

### Database Schema Specification

#### TABLE 1: `users` (Minimal — Demo only)

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(255) NOT NULL UNIQUE,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(512) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_username ON users(username);
```

**SQLAlchemy Model Patterns:**
- Use `SERIAL` for auto-incrementing ID (SQLAlchemy: `Integer, primary_key=True, autoincrement=True`)
- Use `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` (SQLAlchemy: `DateTime, default=func.now()`)
- Use `VARCHAR(255)` with `UNIQUE` (SQLAlchemy: `String(255), unique=True`)

#### TABLE 2: `leads` (Core — Main entity)

```sql
CREATE TABLE leads (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    company VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    phone VARCHAR(20),
    status VARCHAR(50) DEFAULT 'Nuevo',
    notes TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Indexes for query performance
CREATE INDEX idx_leads_email ON leads(email);
CREATE INDEX idx_leads_status ON leads(status);
CREATE INDEX idx_leads_updated_at ON leads(updated_at DESC);

-- Constraint for status validation
ALTER TABLE leads ADD CONSTRAINT check_status_valid 
    CHECK (status IN ('Nuevo', 'En contacto', 'Propuesta enviada', 'Cerrado'));
```

**SQLAlchemy Model Pattern:**
```python
from sqlalchemy import String, Text, DateTime, func, CheckConstraint, Index
from sqlalchemy.orm import declarative_base

Base = declarative_base()

class Lead(Base):
    __tablename__ = "leads"
    
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    name: Mapped[str] = mapped_column(String(255), nullable=False)
    company: Mapped[str] = mapped_column(String(255), nullable=False)
    email: Mapped[str] = mapped_column(String(255), nullable=False, unique=True)
    phone: Mapped[str | None] = mapped_column(String(20), nullable=True)
    status: Mapped[str] = mapped_column(String(50), default="Nuevo", nullable=False)
    notes: Mapped[str | None] = mapped_column(Text, nullable=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=func.now(), nullable=False)
    updated_at: Mapped[datetime] = mapped_column(DateTime, default=func.now(), nullable=False)
    
    __table_args__ = (
        CheckConstraint(
            "status IN ('Nuevo', 'En contacto', 'Propuesta enviada', 'Cerrado')",
            name="check_status_valid"
        ),
        Index("idx_leads_email", "email"),
        Index("idx_leads_status", "status"),
        Index("idx_leads_updated_at", "updated_at", postgresql_using="DESC"),
    )
```

#### TABLE 3: `lead_audit_log` (Audit trail — Compliance + debugging)

```sql
CREATE TABLE lead_audit_log (
    id BIGSERIAL PRIMARY KEY,
    lead_id INTEGER NOT NULL REFERENCES leads(id) ON DELETE CASCADE,
    event_type VARCHAR(50) NOT NULL,
    old_value JSONB,
    new_value JSONB,
    description TEXT,
    created_by_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    meta JSONB
);

-- Indexes for query performance
CREATE INDEX idx_audit_lead_id ON lead_audit_log(lead_id);
CREATE INDEX idx_audit_created_at ON lead_audit_log(created_at DESC);
CREATE INDEX idx_audit_event_type ON lead_audit_log(event_type);
```

**SQLAlchemy Model Pattern:**
```python
from sqlalchemy import BigInteger, ForeignKey, JSON, Text, TIMESTAMP
from sqlalchemy.orm import relationship

class LeadAuditLog(Base):
    __tablename__ = "lead_audit_log"
    
    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    lead_id: Mapped[int] = mapped_column(Integer, ForeignKey("leads.id", ondelete="CASCADE"), nullable=False)
    event_type: Mapped[str] = mapped_column(String(50), nullable=False)
    old_value: Mapped[dict | None] = mapped_column(JSON, nullable=True)
    new_value: Mapped[dict | None] = mapped_column(JSON, nullable=True)
    description: Mapped[str | None] = mapped_column(Text, nullable=True)
    created_by_id: Mapped[int | None] = mapped_column(Integer, ForeignKey("users.id", ondelete="SET NULL"), nullable=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=func.now(), nullable=False)
    meta: Mapped[dict | None] = mapped_column(JSON, nullable=True)
    
    # Relationship
    lead: Mapped[Lead] = relationship("Lead", foreign_keys=[lead_id])
    
    __table_args__ = (
        Index("idx_audit_lead_id", "lead_id"),
        Index("idx_audit_created_at", "created_at", postgresql_using="DESC"),
        Index("idx_audit_event_type", "event_type"),
    )
```

        sa.Column('phone', sa.String(20), nullable=True),

        sa.Column('description', sa.Text(), nullable=True),

## 🎓 DEVELOPER NOTES & GUARDRAILS

### Critical Decisions Explained

**Why Alembic, not raw SQL?**
- Versioning: Every schema change is tracked, auditable
- Reversibility: Downgrade safely without manual SQL
- Team Collaboration: Migrations merge cleanly in Git
- CI/CD Ready: Automated schema updates in production

**Why JSONB for audit trail?**
- Flexible: Audit log stores arbitrary old/new values
- Queryable: Can filter by audit changes without additional schema
- Performance: GIN indexes on JSONB if needed later
- Future-Proof: Handles schema evolution gracefully

**Why Separate Audit Table, not Triggers?**
- In this demo: Simplicity, no trigger complexity
- Future: More control for audit strategies (async logging, external systems)
- Developer Experience: Easier to test & debug

**Why Index on updated_at DESC?**
- Query Pattern: "Show me most recently modified leads" → ORDER BY updated_at DESC
- Index Optimization: DESC order avoids sort in query plan

### Implementation Anti-Patterns (AVOID)

❌ **DON'T:** Use `datetime.datetime.now()` as default in SQLAlchemy
- SQLAlchemy evaluates this at import time, not insert time
- **DO:** Use `func.now()` — evaluated at DB insert time

❌ **DON'T:** Use `engine.begin()` with asyncio
- Not compatible with async/await
- **DO:** Use `async with engine.connect()` or `async_session_maker()`

❌ **DON'T:** Skip downgrade() in migration
- Future developers need safe rollback
- **DO:** Always implement both upgrade() and downgrade()

❌ **DON'T:** Leave migration file auto-generated without review
- Alembic sometimes misses constraints or indices
- **DO:** Review migration, add explicit DDL if needed
