## 🔴 CHALLENGES & DISCOVERIES

### Challenge 1: Hidden Drag&Drop Bug in E4-S3
**Symptom:** Drag&drop UI rendered correctly but drag events didn't trigger mutations

**Root Cause (Two Layers):**

**Layer 1: React Query Data Structure Mismatch**
- `useLeads()` returns: `array` directly
- `onMutate` assumed: `{data: array}` structure
- Result: `Cannot read properties of undefined (reading 'data')`

**Layer 2: Missing Query Invalidation**
- API calls succeeded but UI never refetched
- `onSuccess` was missing `queryClient.invalidateQueries()`

**How It Was Missed:**
- Unit tests passed (mocked React Query state correctly)
- Component tests passed (drag/drop events fired)
- **Gap:** No E2E testing to catch integration bugs

**Resolution:**
1. Fixed `onMutate` to handle array structure directly
2. Added `invalidateQueries()` in `onSuccess`
3. Enhanced logging at validation checkpoints
4. Verified with manual E2E: drag works end-to-end

**rauna's Assessment:** This bug should have been caught in code review, not discovered in testing. Indicates need for stronger React Query pattern review checklist.

### Challenge 2: E4-S2 Story File Structure Issues
**Issue:** E4-S2.md didn't have expected structure during initial development

**Impact:** Development clarity suffered; had to improve structure mid-epic

**rauna's Requirement:** E5 story files MUST follow strict template from day 1. No mid-epic structure fixes.

**Action:** Create `STORY_TEMPLATE.md` before E5 planning to prevent recurrence.

### Challenge 3: Testing Gap Between Unit and E2E

**Conclusion:** Invest in code review; it's not overhead, it's quality insurance.

### Insight 2: React Query Data Structure Assumptions Are Fragile
**Pattern Risk:** Code assumes query cache structure without explicit validation

**Fix Applied in E4-S3:**
```typescript
// Before (broke):
queryClient.setQueryData(['leads'], (old: any) => ({
  ...old,
  data: old.data.map(...) // ❌ Assumes {data: array}
}));

// After (works):
queryClient.setQueryData(['leads'], (old: any) => {
  if (!Array.isArray(old)) return old; // ✅ Defensive
  return old.map(...); // ✅ Correct for array structure
});
```

**Impact on E5:** Timeline feature will likely use React Query. Must apply this pattern correctly from day 1.

### Insight 3: Pattern Reusability Requires Active Documentation
**Why Velocity Improved:** E4-S1 patterns were explicit → E4-S2, E4-S3 copied them quickly

**Risk for E5:** Without formal documentation, patterns decay or variants emerge

**Action:** Create `FILTER_PATTERNS.md` + `REACT_QUERY_PATTERNS.md` before E5 starts

### Insight 4: Unit Tests Alone Are Insufficient
**Gap Found:** Unit tests passed; E2E testing revealed integration bugs

**Why This Matters for E5:** Timeline feature will have complex state interactions (user events → mutations → timeline updates). Unit tests won't catch cross-component timing issues.

**Requirement:** E2E testing framework must be in place before E5-S1 development starts.
