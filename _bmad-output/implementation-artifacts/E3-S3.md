## 🎯 STORY REQUIREMENTS

### User Story Statement

**Como** ejecutivo de venta,  
**quiero** arrastrar leads entre columnas en el Kanban para cambiar su estado,  
**para que** actualizar el estado sea intuitivo y rápido sin salir del dashboard.

### Business Value

1. **UX Fluida:** Drag-drop es patrón estándar en Kanban → usuarios esperan esto
2. **Productividad:** Cambiar estado en 1 acción vs 2-3 clicks
3. **Visualización:** Ver leads mover entre columnas da feedback satisfactorio
4. **MVP Completo:** Kanban sin drag-drop se siente incompleto para MVP

### Acceptance Criteria

#### AC-1: Drag visual feedback
```gherkin
Given que empiezo a arrastrar un lead card
When la card está siendo arrastrada
Then:
  - La card tiene opacity 0.6 (semi-transparent)
  - Aparece sombra enlargada (dragging shadow)
  - El cursor cambia a "grabbing" (no "grab")
```

#### AC-2: Drop en columna válida
```gherkin
Given que arrastro un lead sobre una columna válida
When suelto el mouse
Then:
  - El lead se mueve a la nueva columna INMEDIATAMENTE (optimistic update)
  - El contador de la columna origen disminuye
  - El contador de la columna destino aumenta
  - Se envía PATCH /api/leads/{id}/status al backend con nuevo status
```

#### AC-3: Optimistic update
```gherkin
Given que arrastré un lead y lo solté
When el estado se actualiza en la UI
Then:
  - La UI cambia ANTES de que el servidor responda
  - El lead aparece en la nueva columna sin delay
  - No esperar al backend para reflejar cambio
```

#### AC-4: Backend sync y confirmación
```gherkin
Given que la UI se actualizó optimisticamente
When el backend responde al PATCH
Then:
  - La BD está sincronizada con la UI
  - Si el servidor responde la posición está confirmada
  - Si el servidor responde error → ver AC-5
```

#### AC-5: Error handling y revert
```gherkin
Given que arrastré un lead y la request al backend falló
When se detecta el error (status 4xx o 5xx)
Then:
  - El lead vuelve a su posición anterior en la UI
  - Se muestra toast rojo: "Error al cambiar estado. Reintentando..."
  - Se hace retry automático con exponential backoff
```

#### AC-6: Retry logic
```gherkin
Given que la request falló (error de red o 5xx)
When se detecta el fallo
Then:
  - Retry 1: 100ms después
  - Retry 2: 200ms después
  - Retry 3: 400ms después
  - Si retry 3 falla → mostrar toast: "No se pudo cambiar estado. Intenta manualmente"
  - Si algún retry tiene éxito → toast verde: "Estado actualizado"
```

#### AC-7: Disable drag durante sync
```gherkin
Given que acabo de arrastrar un lead (enviando request)
When intento arrastrar otro lead mientras se sincroniza
Then:
  - El drag está deshabilitado
  - Aparece overlay semi-transparente con spinner
  - El usuario no puede hacer otra acción de drag
  - Después del sync, el drag se re-habilita
```

#### AC-8: Animación suave
```gherkin
Given que arrastro un lead
When el lead se mueve entre columnas
Then:
  - La transición visual es suave (duration 200-300ms)
  - No hay layout shift abrupto (no jarring)
  - La animación usa CSS transitions (no brusca)
```

#### AC-9: Solo drag a columnas válidas
```gherkin
Given que arrastro un lead
When intento soltarlo fuera de una columna válida (ej: barra lateral, area inválida)
Then:
  - La acción se cancela
  - El lead vuelve a su posición original sin cambios
  - No se envía request al backend
```

#### AC-10: Reordenar dentro de columna
```gherkin
Given que estoy en la columna "Nuevo"
When arrastro un lead a diferente posición DENTRO DE LA MISMA COLUMNA
Then:
  - El lead se reordena visualmente
  - El status NO cambia (sigue siendo "Nuevo")
  - No se envía request al backend (futuro feature: persistir orden)
```

#### AC-11: Multi-device support
```gherkin
Given que accedo en mobile/tablet
When intento arrastrar un lead
Then:
  - El drag funciona con touch
  - El comportamiento es igual que desktop
  - El feedback visual es igual
```

#### AC-12: Accesibilidad
```gherkin
Given que uso screen reader
When interactúo con drag-drop
Then:
  - El cambio de estado es anunciado por screen reader
  - Los contadores actualizados son anunciados con aria-live
```

#### 3. **useKanbanDragDrop.ts - New Hook**

```typescript
import { useState } from 'react';
import { useMutation, useQueryClient } from '@tanstack/react-query';
import toast from 'react-hot-toast';
import { DropResult } from 'react-beautiful-dnd';

const LEAD_STATUSES = ['Nuevo', 'En contacto', 'Propuesta enviada', 'Cerrado'];

export const useKanbanDragDrop = () => {
  const [isDragging, setIsDragging] = useState(false);
  const queryClient = useQueryClient();

  // Mutation for PATCH /api/leads/{id}/status
  const changeStatusMutation = useMutation({
    mutationFn: ({ id, newStatus }: { id: number; newStatus: string }) =>
      fetch(`/api/leads/${id}/status`, {
        method: 'PATCH',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ status: newStatus }),
      }).then(r => {
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        return r.json();
      }),
    
    onMutate: async ({ id, newStatus }) => {
      // Optimistic update
      await queryClient.cancelQueries({ queryKey: ['leads'] });
      const previousLeads = queryClient.getQueryData(['leads']);
      
      queryClient.setQueryData(['leads'], (old: any) => ({
        ...old,
        data: old.data.map((lead: any) =>
          lead.id === id ? { ...lead, status: newStatus } : lead
        ),
      }));

      return { previousLeads };
    },

    onError: (err, vars, context) => {
      // Revert on error
      if (context?.previousLeads) {
        queryClient.setQueryData(['leads'], context.previousLeads);
      }
      toast.error('Error al cambiar estado. Reintentando...');
    },

    onSuccess: (data, { id, newStatus }) => {
      toast.success(`Lead movido a "${newStatus}"`);
      // Data already updated optimistically
    },

    retry: (failureCount) => {
      if (failureCount > 3) return false;
      return true; // Use default exponential backoff
    },
  });

  const handleDragEnd = (result: DropResult) => {
    const { source, destination, draggableId } = result;

    // Draggable ID format: "lead-{id}"
    const leadId = parseInt(draggableId.split('-')[1]);

    // No destination or same position
    if (
      !destination ||
      (source.droppableId === destination.droppableId &&
        source.index === destination.index)
    ) {
      return;
    }

    const newStatus = destination.droppableId;
    const oldStatus = source.droppableId;

    // Same column = just reorder (no status change)
    if (oldStatus === newStatus) {
      // TODO: Persist reordering in future epic
      return;
    }

    // Validate status
    if (!LEAD_STATUSES.includes(newStatus)) {
      toast.error('Destino inválido');
      return;
    }

    // Disable dragging during sync
    setIsDragging(true);

    // Trigger mutation
    changeStatusMutation.mutate(
      { id: leadId, newStatus },
      {
        onSettled: () => setIsDragging(false),
      }
    );
  };

  return { isDragging, handleDragEnd };
};
```
