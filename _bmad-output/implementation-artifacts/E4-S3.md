## 📋 STORY CONTEXT

### Objetivo
Agregar status filter tabs en el header del Kanban, permitiendo al usuario ver solo 1-2 columnas de status (o todas).

### Problema que Resuelve
- Kanban con 50+ leads es abrumador (muchas columnas/mucho scroll)
- Usuario quiere enfocarse en un status específico
- Ejecutivo quiere ver solo "Propuesta" para revisar conversiones

### Decisión de Planning Review
> **Implementación:** Tabs en header: [Todos] [Nuevo] [En contacto] [Propuesta] [Cerrado]  
> **Independiente de E4-S1:** E4-S1 es search + priority filter. E4-S3 es status filter.  
> **Se combina con E4-S1:** Si user busca "juan" + filtra "Propuesta" → solo leads "juan" en Propuesta.

### User Story
> **Como** Ejecutivo de Ventas  
> **Quiero** filtrar el Kanban para ver solo un status  
> **Para que** pueda enfocarme en un stage específico del pipeline

### Component Implementation
```typescript
// components/StatusFilterTabs.tsx

export function StatusFilterTabs() {
  const { selectedStatus, setSelectedStatus } = useKanbanStore();
  
  const tabs = [
    { value: 'all', label: 'Todos' },
    { value: LeadStatus.NUEVO, label: 'Nuevo' },
    { value: LeadStatus.EN_CONTACTO, label: 'En contacto' },
    { value: LeadStatus.PROPUESTA, label: 'Propuesta' },
    { value: LeadStatus.CERRADO, label: 'Cerrado' }
  ];
  
  return (
    <div className="flex gap-2 pb-4 border-b border-gray-200 overflow-x-auto">
      {tabs.map(tab => (
        <button
          key={tab.value}
          onClick={() => setSelectedStatus(tab.value)}
          onKeyPress={(e) => e.key === 'Enter' && setSelectedStatus(tab.value)}
          className={`
            px-4 py-2 whitespace-nowrap font-medium rounded
            ${selectedStatus === tab.value 
              ? 'bg-blue-500 text-white border-b-2 border-blue-600' 
              : 'bg-gray-100 text-gray-700 hover:bg-gray-200'}
            transition-colors duration-200
          `}
          aria-pressed={selectedStatus === tab.value}
        >
          {tab.label}
        </button>
      ))}
    </div>
  );
}

// KanbanBoard.tsx - render columns conditionally
export function KanbanBoard() {
  const { visibleColumns, filteredLeads } = useKanbanStore();
  
  return (
    <div>
      <StatusFilterTabs />
      
      <div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4">
        {visibleColumns.map(status => (
          <KanbanColumn
            key={status}
            status={status}
            leads={filteredLeads.filter(l => l.status === status)}
          />
        ))}
      </div>
    </div>
  );
}
```

## � RESOLUTION: Drag&Drop Functionality Issue (Discovered & Fixed)

### Problem Discovered During E4-S3 Implementation
During integration testing of the status filter tabs with drag&drop interactions, discovered that **leads could not be dragged between columns to change status**, even though the UI appeared functional.

### Root Cause Analysis
The issue had **two independent layers** preventing drag&drop from working:

#### Layer 1: Data Structure Mismatch (onMutate failure)
- **Symptom:** Console error: `TypeError: Cannot read properties of undefined (reading 'data')`
- **Root Cause:** The `onMutate` optimistic update function assumed query data structure was `{ data: [...] }`, but `useLeads()` hook stores data directly as `[...]` (array)
- **Location:** `frontend/src/hooks/useKanbanDragDrop.ts`, line 65-79

**Before (broken):**
```typescript
queryClient.setQueryData(['leads'], (old: any) => ({
  ...old,
  data: old.data.map((lead: any) =>
    lead.id === id ? { ...lead, status: newStatus } : lead
  ),
}));
```

**After (fixed):**
```typescript
queryClient.setQueryData(['leads'], (old: any) => {
  if (!Array.isArray(old)) {
    console.log('⚠️ Cannot perform optimistic update: expected array');
    return old;
  }
  return old.map((lead: any) =>
    lead.id === id ? { ...lead, status: newStatus } : lead
  );
});
```

#### Layer 2: UI Not Refreshing (onSuccess missing invalidation)
- **Symptom:** API request succeeded (✅ Mutation success in console), but UI didn't update
- **Root Cause:** `onSuccess` handler called `toast.success()` but never invalidated the query cache, so UI kept old data
- **Location:** `frontend/src/hooks/useKanbanDragDrop.ts`, line 102-105

**Before (broken):**
```typescript
onSuccess: (_data, { newStatus }) => {
  toast.success(`Lead movido a "${newStatus}"`);
  // Data already updated optimistically
},
```

**After (fixed):**
```typescript
onSuccess: (data, { newStatus }) => {
  console.log('✅ Mutation success:', data);
  // Invalidate leads query to refetch with new status
  queryClient.invalidateQueries({ queryKey: ['leads'] });
  toast.success(`Lead movido a "${newStatus}"`);
},
```

1. ✅ Added defensive checks in `onMutate` to handle array-type query data

3. ✅ Added `queryClient.invalidateQueries()` in `onSuccess` to trigger server-confirmed refetch
4. ✅ Enhanced logging at each validation checkpoint: ID parsing → status validation → mutation execution → optimistic update → onSuccess
